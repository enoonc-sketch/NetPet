## 2. 唯一会产生网络流量的功能
- **反向 DNS（隐私页“解析主机名”，默认关闭）**：把连接记录里的对方 IP 交给系统 DNS 服务器查询。会让 DNS 服务器知道这些 IP。开启前页面里已写明。
- 其余功能只读取本机系统计数器、系统命令输出和本地文件。

## 3. 数据去向
- 所有采集结果只写入 `%APPDATA%\NetPet\data
etpet.db`。没有任何上传、同步、统计上报。
- 页面 CSP 为 `default-src 'self'`，渲染进程不能请求任何远程地址，也不加载远程脚本。
- 导出 CSV、备份数据库只会写到你在对话框里选择的位置。

## 4. 不采集的内容（代码层面核对）
- 不读取数据包/通信内容，不做 TLS 解密：只调用连接表（元数据）和网卡计数器。
- 不记录键盘输入、屏幕截图、浏览器历史、用户文件：代码中没有相关调用。
- 不修改系统配置：检查用的 PowerShell 命令都是只读（Get-*）；例外是你主动点击的“Defender 快速扫描”（调用 Start-MpScan）。唯一的系统写操作是开机自启登录项，由用户开关控制。
- 不自动结束进程：已移除结束进程功能。

## 5. 本次审查发现并已修复的问题
- 反向 DNS 默认开启会向 DNS 服务器泄露连接的 IP → 已改为默认关闭、需用户主动开启。

## 6. 按程序流量（ETW，v1.3.0 新增）
- 原生组件启动 ETW 内核会话，只收 TcpIp/UdpIp 的 Send/Recv 事件；每个事件只用进程 ID 和字节数（size），不读通信内容、不记目的 IP/端口、不解密 TLS。
- 数据只进本地库 `proc_traffic`（程序名 + 累计收发字节），不上传。
- 默认关闭；开启需要管理员权限，NetPet 不自动提权、不弹窗索权；关闭开关立即停止 ETW 会话，退出时也会停掉，不留后台会话。
- 限制：UDP 提供方 GUID 未经核实，可能未计入；`size` 偏移是假设值，真机校准前不要当精确账单。
