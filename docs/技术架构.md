# NetPet 技术架构（v1.2）

与规范书的差异：当前用 **Electron + 原生 JavaScript + three.js**，没有迁移到 TypeScript + React；数据库用 Node 内置 `node:sqlite`（Electron 37 / Node 22），不需要编译原生模块。例外：按程序流量（1.3.0）用了一个原生组件 `native/procnet`（C++ + N-API），因为 ETW 内核会话只能在原生层启动，见下表新增行。

| 层 | 文件 | 说明 |
|---|---|---|
| UI 展示层 | `dashboard.html`、`panel.html` | 完整窗口 6 个页签；单击展开的小面板 |
| 宠物动画层 | `index.html`、`src/pets3d.js` → `pets.bundle.js` | 18 只 three.js 程序化 3D 宠物；WebGL 不可用时退回 2D |
| 状态机 | `petstate.js` | 9 个状态，持续时间防抖 + 优先级 + 最短停留；用户可关闭部分提醒 |
| 系统信息采集层 | `main.js`（tick）、`systeminformation` | 网卡计数器、CPU、内存、温度、磁盘、GPU、电池 |
| 网络统计层 | `main.js`（readNet/connTick） | A 网卡总流量；C 连接元数据；B 按进程流量**未实现** |
| 系统健康检查层 | `security.js`、`fullscreen.js` | 只读检查，输出 正常/注意/异常/无法检测 + 依据 + 建议 |
| 本地数据库层 | `db.js` | SQLite：network_statistics、adapter_information、connection_records、hardware_statistics、system_health、warning_records、settings、proc_traffic（按程序名累计收发字节）；保留期限、清空、`VACUUM INTO` 备份、损坏自动重建 |
| 按程序流量层 | `native/procnet/procnet.cpp` + `procnet.js` | ETW 内核日志会话（只开 NETWORK_TCPIP），按 PID 累计 TCP/UDP 字节；JS 层每 2 秒换算速率、按程序名聚合，每 30 秒落库。默认关闭，需管理员权限；原生组件缺失时如实报不可用 |
| 权限管理层 | `main.js`（privacy 开关） | 每项功能独立开关，关闭即不采集 |
| 设置管理层 | `main.js`（applyPatch）+ `settings` 表 | 所有写入参数白名单校验 |

## Electron 安全措施
contextIsolation=true、nodeIntegration=false、sandbox=true；preload 只暴露白名单通道（invoke/on/send 各有清单）；主进程校验消息来源窗口并对参数做类型/范围校验；禁止页面跳转与新窗口；拒绝所有权限请求；页面 CSP 限制只加载本地脚本；不加载任何远程脚本。

## 进程与资源
后台子进程（PowerShell 检查、全屏检测、systeminformation 常驻 PowerShell）都会在退出时结束（`before-quit` 中 killAll / stop / powerShellRelease）。
